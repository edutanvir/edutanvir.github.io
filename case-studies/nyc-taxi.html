The short version

From trip records to useful answers.

NYC publishes taxi trip records as big data files. On their own, they're just rows. I built a small Azure pipeline that brings those files in, stores them in the cloud, and lets me ask questions about trips, fares, distances and payment types using plain SQL.

Below you'll find how the pieces fit together, what the results look like, and what I'd improve next. No jargon without an explanation.

Why this was worth building

Raw files aren't much use on their own.

Before anyone can analyse trip data, someone has to bring the files in, keep them organised, and make them easy to query. That plumbing isn't glamorous, but everything else depends on it. It's the part of data engineering I enjoy most.

In plain English: three services, three jobs

Azure Data Factory is the delivery truck: it moves the files. Data Lake Storage is the shelving: it keeps them organised. Synapse is the front desk: it's where you ask questions in SQL.

Reporting

How can SQL queries support the reporting someone would actually need?

A simplified example of the kind of question I asked (table and column names are illustrative): 

SELECT payment_type,
       COUNT(*)         AS trips,
       SUM(fare_amount) AS total_fares,
       SUM(tip_amount)  AS total_tips
FROM   trips
GROUP BY payment_type
ORDER BY trips DESC;

Reflection

What I'd improve next.

This project turns raw trip records into a layer of data that anyone comfortable with SQL can query. With more time, I'd add:

  • Automated data-quality checks, so bad or missing records are caught before they reach a report.
  • Performance tuning for larger volumes of trips.
  • Scheduled refreshes, so the data stays up to date without anyone pressing a button.
The most useful pipeline is the one nobody has to think about.
